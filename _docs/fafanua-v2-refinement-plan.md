# Fafanua Website — V2 Refinement Plan

## Objective

Refine the current live Fafanua V2 website before the next SEO-focused iteration.

The current visual direction is approved and should be preserved.

This is **not** a redesign.

The objective is to improve:

- positioning clarity
- section purpose
- visual density
- the system diagram
- the About section
- the future-ready visual
- consistency between the brand promise and service positioning

The current core proposition should remain:

> **Trusted Data. Better Decisions.**

with the supporting brand promise:

> **Build a data foundation you can trust.**

The site should continue to position Fafanua as a company that helps organisations **build, strengthen and operate trusted data foundations** for reporting, analytics and operations.

---

# 1. Core Positioning Principle

Do not assume prospective clients have no data infrastructure.

Many target organisations will already have:

- reporting teams
- BI tools
- operational systems
- databases
- data warehouses
- data engineers
- dashboards
- spreadsheets
- existing data platforms

The Fafanua proposition is therefore not limited to greenfield implementation.

Fafanua should communicate that it can help organisations:

- build new data foundations
- strengthen existing platforms
- connect fragmented systems
- standardise business definitions
- improve data quality
- improve governance
- operationalise trusted data
- support ongoing reliability and platform operation

Use this principle consistently across homepage copy and future SEO content.

# 2. Hero Section

## Keep

Retain the current visual structure:

> **Trusted Data. Better Decisions.**

Directly beneath it:

> **Build a data foundation you can trust.**

Keep the dark technical hero, grid treatment, CTA hierarchy and current visual scale.

## Update supporting copy

Replace the current hero supporting paragraph with:

> **Fafanua helps organisations build and strengthen the data foundations behind their reporting, analytics and operations — connecting fragmented systems, improving trust in data, and turning organisational information into reliable business intelligence.**

### Rationale

This copy better reflects the target market.

It works for:

- organisations building a data platform for the first time
- organisations that already have reporting or data teams
- organisations that already have warehouses or pipelines but lack consistency or trust
- organisations that need to improve existing infrastructure rather than replace it

# 5. System / Data Flow Diagram

The current diagram is conceptually correct but visually too close to an architecture-document diagram.

It should become more visually integrated with the V2 design language.

## Core flow to preserve

> **Operational Systems**  
> ↓  
> **Data Engineering & Integration**  
> ↓  
> **Data Warehouse & Semantic Models**  
> ↓  
> **Quality + Governance**  
> ↓  
> **Analytics & Reporting**  
> ↓  
> **Reverse ETL / Operational Activation**

## Important change

The final activation stage should visually connect back to operational systems.

Reverse ETL is not the end of a linear pipeline.

The diagram should communicate a loop:

> **Operational systems → trusted data foundation → analytics → operational systems**

This is important to the commercial proposition because Fafanua supports both analytical use and operational activation.

## Preferred visual treatment

Upgrade the current stacked rectangles into a more cohesive system visual.

Possible approaches:

- layered stack
- connected architecture bands
- vertically layered system model
- restrained isometric treatment
- circular or looped flow

Keep the diagram simple enough to understand quickly.

Do not create a fake infrastructure screenshot.

## Labels to retain

- DATA SOURCES
- INTEGRATION LAYER
- TRUST LAYER
- DECISION LAYER
- ACTIVATION LAYER

The diagram should remain accessible and understandable without relying only on colour.

# 8. How We Work

The current content is correct but the section has too much vertical space relative to its information density.

## Keep process

> **Assess → Design → Build → Govern**

## Reduce vertical spacing

Reduce overall section padding by approximately **20–30%**, subject to responsive testing.

The section should remain spacious but should not feel empty.

## Add a concise output / deliverable per stage

### 01 Assess

Current purpose:

> Understand the organisation's systems, data, reporting needs, constraints and priorities.

Add short output:

> **Systems & needs assessment**

### 02 Design

Current purpose:

> Define the target architecture, business concepts, delivery roadmap and controls.

Add:

> **Architecture & delivery roadmap**

### 03 Build

Current purpose:

> Implement pipelines, data models, quality checks, governance assets and reporting products.

Add:

> **Pipelines, models & analytical products**

### 04 Govern

Current purpose:

> Establish ownership, monitoring, documentation, traceability and continuous improvement.

Add:

> **Ownership, monitoring & continuous improvement**

Keep these outputs visually secondary.

# 14. SEO Handoff Principle

After these refinements, the next major workstream is SEO and search discoverability.

Do not overload the homepage with search phrases.

The homepage should remain brand-led.

SEO should primarily be strengthened through:

- service landing pages
- solution landing pages
- metadata
- structured data
- internal linking
- sitemap
- canonical URLs
- Search Console
- high-quality Insights content later

The homepage should continue to communicate the broader positioning naturally.
