# Fafanua — Data Trust Assessment & Problem-Framing Enhancement

## Objective

Refine the existing homepage flow so that the **Data Trust Assessment** is clearly understood as the standard starting point for working with Fafanua, while preserving the existing approved content and visual language.

This is an **enhancement of the current implementation**, not a redesign.

Do not add a second Data Trust Assessment section.

Do not replace the existing homepage structure.

The current homepage already contains the right concept. The goal is to strengthen:

1. the problem-framing section immediately before the assessment;
2. the hierarchy and positioning of the existing Data Trust Assessment;
3. the transition from assessment findings into Fafanua's capabilities.

---

# 1. Preserve the Existing Data Trust Assessment

The current homepage already includes the key proposition:

> **Know where every number comes from.**

This headline should remain.

The existing explanatory copy should also remain substantially intact:

> The Data Trust Assessment takes the numbers your leadership relies on most and traces each one from the report back to its source. It runs for three weeks at a fixed fee.

This already answers the three most important commercial questions:

- what the assessment does;
- how long it takes;
- how it is priced.

Do not replace this with a generic audit-style explanation.

---

# 2. Clarify That This Is the Starting Point

The current implementation can still be interpreted as one offering among several.

Strengthen the hierarchy so the Data Trust Assessment is clearly presented as the **entry engagement**.

Add a small label above the assessment section such as:

> **START WITH TRUST**

and make the engagement name explicit:

> **DATA TRUST ASSESSMENT**

Then retain the existing large statement:

> **Know where every number comes from.**

Preferred hierarchy:

```text
START WITH TRUST

DATA TRUST ASSESSMENT

Know where every
number comes from.
```

The large statement should remain the dominant visual headline.

The label and engagement name should establish context without competing with it.

---

# 3. Commercial Positioning

The Data Trust Assessment should be presented as the standard way a customer starts working with Fafanua.

The commercial journey is:

> **Data Trust Assessment → Prioritised Roadmap → Implementation → Managed Services**

The assessment is **not** a seventh service.

The six service lines describe what Fafanua can do.

The Data Trust Assessment describes **how a customer begins**.

This should help answer the prospect's question:

> **Where do we start?**

The answer should be clear:

> Start with the numbers leadership relies on most, determine where trust breaks down, and then strengthen the right parts of the data foundation.

---

# 4. Improve the Problem-Framing Section

The section immediately before the Data Trust Assessment currently contains the statement:

> Most organisations already have data, reporting and operational systems. The challenge is making the information flowing through them connected, consistent and trusted.

The content is correct.

The problem is the current visual composition: the text sits too far to one side of the page, leaving a large amount of unused space and making the section feel accidental rather than deliberate.

Replace the current one-sided layout with an **intentional two-column problem-framing composition**.

---

# 5. Recommended Two-Column Layout

Use the existing page container and align the section with the site's broader grid.

## Left column

Use a small eyebrow:

> **THE PROBLEM**

Under it, include a concise framing statement such as:

> Organisations rarely lack data. The challenge is knowing whether the numbers used to run the business are connected, consistent and trustworthy.

This left column should remain relatively compact.

It provides context rather than competing with the main statement.

---

## Right column

Retain the existing core message as the dominant text:

> **Most organisations already have data, reporting and operational systems. The challenge is making the information flowing through them connected, consistent and trusted.**

This should use a larger editorial text treatment.

The right column should visually carry more weight than the left.

The layout should feel intentionally asymmetrical, not like text accidentally pushed to one side.

---

# 6. Add a Transition Into the Assessment

At the bottom of the problem-framing section, add a short line that bridges directly into the Data Trust Assessment.

Recommended:

> **That is why Fafanua starts by tracing the numbers leadership relies on most back to their source.**

This should be visually secondary to the main problem statement.

Its purpose is to make the next section feel like the answer to the problem just introduced.

The homepage narrative should become:

```text
Existing systems and reporting
        ↓
Trust is uncertain
        ↓
Start with trust
        ↓
Data Trust Assessment
        ↓
Find the gaps
        ↓
Prioritise what matters
        ↓
Apply the right capabilities
```

---

# 7. Existing Assessment Visual

Retain the existing illustrative assessment card.

The current structure is useful because it already shows:

- example leadership metrics;
- what each metric is traced through;
- trust-rating outcomes.

Retain representative metric names such as:

- Revenue
- Active Customers
- Portfolio at Risk
- Programme Outcomes
- Cost per Customer

Do not invent:

- numeric values;
- currencies;
- percentages;
- customer names;
- assessment findings.

---

# 8. Clarify the Example Labels

Prefer:

> **Illustrative example**

instead of:

> Illustrative example. Sample data only.

There are no real numerical values in the visual, so `Sample data only` is unnecessary.

Rename:

> **Sample metrics**

to:

> **Example leadership metrics**

This is more precise and better reflects the purpose of the assessment.

---

# 9. Preserve the Existing Trace Concept

The existing visual currently shows:

> Each traced through

followed by:

- Definition
- Calculation
- Source systems
- Owner
- Trust rating

Retain this concept.

If space allows, improve the trace sequence slightly so the relationship feels directional rather than merely listed.

Preferred conceptual sequence:

```text
Report
  ↓
Definition
  ↓
Calculation
  ↓
Data model
  ↓
Source system
  ↓
Owner
  ↓
Trust rating
```

Do not introduce a second large reverse-lineage diagram on the homepage.

The existing illustrative card is sufficient if the trace relationship is made clear.

The full methodology can later live on:

```text
/data-trust-assessment
```

---

# 10. Preserve the Existing Deliverables

The current deliverables are strong and should remain.

They currently communicate:

- a lineage map showing how each key number is produced, system by system;
- a trust scorecard rating each number as trusted, trusted with caveats, or not yet trusted, with the reasons;
- shared definitions for terms used differently by teams or branches;
- a prioritised fix list ranked by impact and effort.

These are concrete and understandable.

Do not replace them with abstract consulting language.

Optionally, the last item may become:

> **A prioritised remediation roadmap, ranked by impact and effort**

but only if it fits naturally with the existing plain-language tone.

---

# 11. Strengthen "After the Assessment"

The current `After the assessment` section should explain the commercial transition more clearly.

The existing concept is:

> Most organisations continue with integration and modelling, quality and governance, or reporting built on the traced numbers.

Keep the meaning, but strengthen the hierarchy.

Recommended direction:

## After the assessment

> **The assessment tells us what to fix first.**

Supporting copy:

> The findings become a prioritised roadmap. From there, Fafanua can strengthen the parts of your data foundation that need attention — from integration and modelling to quality, governance and analytics.

This should make the transition into the six capability cards intentional.

The visitor should understand:

> The assessment identifies the problem.

> The capabilities are how Fafanua solves it.

---

# 12. CTA

Retain the existing CTA:

> **Book a data trust assessment →**

This is the correct action for the section.

Where appropriate elsewhere on the homepage, the main commercial CTA may also reference the assessment.

Recommended hierarchy:

Primary:

> **Book a Data Trust Assessment**

Secondary:

> **Discuss your data needs**

Do not remove the broader contact route.

---

# 13. Relationship to Fafanua's Brand Positioning

The assessment should reinforce the protected proposition:

> **Build a data foundation you can trust.**

The connection should be clear:

## Brand promise

> Build a data foundation you can trust.

## Starting point

> Data Trust Assessment

## Method

> Trace the numbers leadership relies on back to source.

## Outcome

> Know what can be trusted, what cannot, why, and what should be fixed first.

Do not optimise away or replace the protected brand proposition.

---

# 14. Visual Design Direction

The problem-framing section and assessment should continue to use the existing Fafanua V2 visual language.

Use:

- restrained typography;
- strong editorial hierarchy;
- generous but intentional spacing;
- existing graphite/paper/teal palette;
- existing grid/container;
- subtle divider lines;
- existing typography tokens;
- existing responsive patterns.

Do not introduce:

- large decorative illustrations;
- stock photography;
- heavy gradients;
- glassmorphism;
- large icon systems;
- a new colour system.

The improvement should come from composition and hierarchy.

---

# 15. Responsive Behaviour

## Desktop

The problem-framing section should use an intentional two-column layout.

Suggested weighting:

- left column: approximately 30–35%;
- right column: approximately 60–65%.

Do not force exact percentages if the existing grid system offers a better equivalent.

The main statement should remain the dominant element.

---

## Tablet

Allow the columns to reduce in contrast or stack if required by available width.

Preserve clear reading order:

1. eyebrow / problem framing;
2. main statement;
3. transition line;
4. Data Trust Assessment.

---

## Mobile

Stack naturally.

Do not attempt to preserve a two-column layout.

Maintain:

- readable line length;
- appropriate heading scale;
- no horizontal overflow;
- clear transition into the assessment section.

---

# 16. Accessibility

Maintain:

- semantic heading order;
- readable line lengths;
- keyboard accessibility;
- browser text enlargement;
- high contrast;
- reduced-motion behaviour;
- no meaning conveyed by position or colour alone.

The two-column desktop presentation must still have a logical DOM order.

---

# 17. Do Not Duplicate Existing Content

Do not:

- add a second Data Trust Assessment section;
- add another large lineage diagram;
- create a seventh service card;
- move the assessment into the services grid;
- rewrite the approved six capabilities;
- remove `Know where every number comes from.`;
- remove the 3-week / fixed-fee proposition;
- remove the existing assessment deliverables;
- redesign unrelated homepage sections.

Where this plan is silent, preserve the current implementation.

---
