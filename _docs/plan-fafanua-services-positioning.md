# Fafanua Website — Coding Agent Implementation Plan

## Objective

Update the existing Fafanua Technologies website to reflect the revised services positioning and commercial structure.

This is **not a redesign from scratch**.

Preserve the current restrained visual style, typography, spacing, card-based layout, and overall brand direction unless a change is explicitly requested below.

The main objective is to improve:

- service naming
- service descriptions
- lifecycle labels
- accordion content
- commercial clarity
- managed-services positioning
- industry-solution positioning
- AI positioning

The website should continue to feel like a professional data and analytics consultancy rather than a generic technology agency.

---

# 1. Core Positioning

The site should position Fafanua as a:

> **Data & Analytics Solutions Partner**

The core message is:

> **Fafanua helps organisations build reliable data foundations, connect fragmented systems, improve trust in their data, and turn information into useful business intelligence.**

Do not position Fafanua primarily as:

- a dashboard agency
- a generic software-development company
- an AI agency
- a cloud reseller
- a staffing company

The website should communicate a complete data lifecycle:

> **Design → Connect → Model → Trust → Govern → Decide → Operate**

The first six stages should appear as the core service capabilities.

“Operate” should be represented separately through Managed Data & Analytics Services.

## Important positioning note

Keep Data Quality & Reliability separate from Data Governance & Metadata.

These are intentionally different propositions.

Quality and reliability answer:

> **Can we trust this data today?**

Governance answers:

> **What does this data mean, who owns it, where did it come from, and how should it be managed?**

Do not merge the two services.

# 13. Reverse ETL Positioning

Reverse ETL must appear explicitly in the site.

It should be represented in:

1. **Data Engineering & Integration**
2. **Managed Data & Analytics Services**

Use the term:

> **Reverse ETL and operational data activation**

The idea to communicate is:

> Fafanua can move trusted analytical data back into the systems where business teams work.

This includes use cases such as:

- pushing customer segments into CRM platforms
- synchronising customer or learner lifecycle status
- activating payment, eligibility, or risk attributes
- exposing trusted metrics inside operational applications
- replacing manually maintained spreadsheet logic with governed warehouse data

Do not create a separate Reverse ETL service card.

# 24. Visual Rules

Maintain the existing visual direction.

Specifically:

- keep the current light, professional aesthetic
- keep typography restrained
- do not introduce gradients without a strong reason
- do not make headings excessively bold
- retain generous whitespace
- preserve desktop and mobile responsiveness
- keep card heights visually balanced where practical
- avoid unnecessary icons or illustrations
- retain accessible contrast
- retain keyboard-accessible accordions

The service cards should feel like part of one system.

Do not visually over-emphasise one service unless explicitly required.

- keyboard interaction works
- focus states are visible
- heading hierarchy remains logical
- text contrast remains accessible

---

# 27. Implementation Constraints

Before making changes:

1. Inspect the existing component structure.
2. Reuse existing components where reasonable.
3. Avoid unnecessary dependency additions.
4. Avoid rewriting working layout or styling without a clear need.
5. Preserve the current Cloudflare deployment setup.
6. Preserve the existing React application structure unless a refactor is clearly justified.
7. Do not break existing routes or anchors.

Prefer incremental modification over large-scale restructuring.
